The hex rule knows about the brand seam, so a deployment does not have to fork it.

`config.ts` is where an installation writes its accent, and that accent cannot be a token — it is the input the tokens are derived from. The no-raw-hex rule forbade it anyway, so a deployment either forked the rule or unenrolled the file. It now allows the seam exactly one hex and checks that the hex IS the accent `BRAND` exports, which is stricter than an exemption: a second hex, or one unrelated to the ramp, still fails. In a tree with no accent — this template — the allowance is zero and the rule behaves exactly as before.
