The board says "step" everywhere a reader can see it. Four strings still said the word `steps` replaced, or the word `slices.kind` replaced, and each of them reached somebody: the step definition in the popover a reader opens ON the board opened with "A column of the board"; the hint under the step panel's Summary field promised "the sentence that makes the column legible"; the step panel's meta line said "different columns on 3 paths"; and a slice that failed validation was refused with "Unknown slice type". They now read "One moment in time, read down every lane at once", "makes the step legible", "different positions on 3 paths" and "Unknown slice kind".

Nothing about the schema moved. `slices.kind` has been `kind` since `21000116000000` and a step has never been called a column in the database — these were the words on screen drifting from the words underneath, which is the defect Check C exists to stop.

**Check C did not stop them, and the interesting half of this release is why.** The guard read JSX text nodes and five props, so a definition living in `src/lib/panelTerms.ts`, a message built in `src/lib/sliceValidation.ts`, a `hint` prop nobody had added to the list, and a sentence assembled into a local before being handed to a prop were each outside its subject. Three of those four edges are now read:

- The reader-facing prop list grew from five to fifteen. It was re-derived from every prop in the tree whose value is a prose string literal, so `hint`, `description`, `summary`, `meta`, `message`, `closeLabel`, `triggerLabel`, `addLabel`, `removeLabel` and `ariaLabel` join the HTML and ARIA attributes it started with. `className`, `d`, `viewBox`, `transform`, `strokeDasharray` and `rel` were looked at and left out: none of them is copy.
- A local whose name ends `Label`, `Text`, `Hint`, `Message`, `Description` or `Caption` is read, so a sentence assembled a few lines above the prop that renders it is no longer invisible. The suffixes cover 77 strings in this tree and every one of them is copy.
- A third subject reads the `.ts` modules whose whole job is the words — `panelTerms.ts` and `sliceValidation.ts`, enrolled by name, each with the sentence saying why. Enrolment rather than the tree, because a blanket sweep of `src/**` was measured rather than assumed: 46 strings in `.ts` files carry a retired spelling and 44 of them are a dev-only arrow catalogue, agent tool descriptions, CSS track names and sample content. Reading them all would need an exemption apiece, and an exemption list is where a real finding hides.

**And the guard's header now says what it still cannot see**, which matters more than the widening: the interpolated half of a template literal, copy assembled anywhere but a named local, a reader-facing prop nobody has added to the list, any `.ts` module not enrolled — and `src/content/coverContent.ts` by name, which is reader-facing copy left unenrolled because it says "one shared context layer" in the software-tier sense that the rename map's `layers` → `lanes` row settles by arguing a `.ts` module reaches no reader. On that one file the argument is untrue. A guard that implies completeness it does not have is worse than one whose blind spots are written down.

**Upgrading a deployment:** nothing to do. No schema, no API and no identifier changed; four sentences on screen read differently, and a deployment holding these files byte-identical picks them up with the template.
